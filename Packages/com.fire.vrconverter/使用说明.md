## 使用前强烈提醒

- ⚠️ **本工具针对复杂 3D 项目的一键 VR 转换存在较高失败率**，特别是在项目包含大量自定义脚本、插件或旧版 XR 配置时。为避免数据损失，**务必在执行前保存场景并完成一次备份或 Git 提交**。
- 如果你已在当前 Unity 项目中启用了 Git 助手（如 Cursor Git 助手或公司内部自动化工具），**请在开始转换前直接调用 Git 助手进行一次提交/打标签**，这样失败后可即时回滚。
- 尚未配置 Git 助手的团队，建议先完成 Git 初始化并安装对应助手，再尝试使用本工具；缺少版本控制是导致失败不可逆的主要风险之一。
- 从 v1.2 起，插件会在执行“一键执行”或“第 2 步”前弹出强制确认窗口，要求你确认已备份；若检测到 Git 助手，还可以直接点击“使用 Git 助手快速备份”完成自动提交。

## 插件简介

**一键 VR 转换工具（VR Project Converter）** 是 Unity 编辑器中的实用窗口，可在数分钟内把普通 Unity 项目配置为基础 VR 项目。它自动完成 XR 依赖包安装、XR Plug-in Management 配置以及场景 VR Rig 构建，帮助初学者避免手动配置的繁琐与易错。

**菜单路径**：`Tools → VR Converter → 一键转换当前项目为VR...`

自 v1.3 起，窗口新增 **傻瓜式/专业模式切换**、**项目体检（Compatibility Insights）** 以及 **VR 模拟设备自动配置**：

- 傻瓜式模式保留“快速开始 + 分步卡片”的一键体验，并会在缺少 XR Device Simulator 时自动导入/配置，方便没有头显的同学直接调试；
- 专业模式可自定义执行步骤、目标平台、场景转换策略，并允许保留原主相机，同时提供“配置 VR 模拟设备”开关；
- 项目体检实时检测渲染管线、XR 包、输入系统、VR 模拟设备与 Git 助手安装情况，提前提示潜在风险。

## 适用场景

- **首次为项目加入 VR 支持**：一键拉起所有必需 XR 依赖。
- **升级旧项目**：快速启用 OpenXR 并生成 XR Origin。
- **教学/培训**：提供简洁的引导式界面，适合初学者动手实践。
- **团队规范化**：统一 XR 配置流程，减少手动步骤差异。

## 快速开始

1. 打开 Unity 项目，确保场景已保存；若已接入 Git 助手，先通过它进行一次“保存进度”或“创建备份”操作。
2. 在菜单中点击 `Tools → VR Converter → 一键转换当前项目为VR...`。
3. 在窗口顶部的 **“一键执行所有步骤（推荐）”** 按钮上悬停，阅读提示后点击执行；此时会弹出**备份确认弹窗**。如果检测到 Git 助手，可直接点击“使用 Git 助手快速备份”创建一条自动提交，完成后才能继续。
4. 如果场景有未保存修改，系统会自动弹出 Unity 的保存对话框，可选择保存、放弃或取消继续执行。
5. 等待 Unity 完成包导入与脚本编译，窗口日志会记录整个过程。
6. 若发现项目尚未配置 XR Device Simulator，工具会自动从 XR Interaction Toolkit Sample 中复制资源至 `Assets/VRConverterGenerated/DeviceSimulator`，并启用“仅在编辑器中自动实例化”，确保没有头显也能调试。
7. 编译结束后，如果需要，可以单独再次点击 **“执行第 2 步”** 来更新 XR 配置和场景，同样会先出现备份确认。
8. 转换成功后，窗口底部的 “Git 助手联动” 卡片会展示 `回滚到转换前版本` 按钮（需要 Git 助手）。点击后会利用 Git 助手执行 `git reset --hard <原提交>`，快速恢复到转换前状态。

## 界面总览

### 1. 头部信息卡

- **标题与简介**：说明工具目标及自动操作范围。
- **状态提示条**：实时显示 Unity 是否处于导入/编译状态，并提示下一步操作建议。

### 2. 模式切换 + 项目体检

- **模式切换工具栏**：在“傻瓜式一键”与“专业模式”之间快速切换，窗口会记住你的选择。
- **项目体检卡片（Compatibility Insights）**：采用两列排版展示渲染管线、XR Management、OpenXR、XR Interaction Toolkit、输入系统、VR 模拟设备与 Git 助手的检测结果，并附上改进建议。

### 3. 快速开始卡片（傻瓜式模式）

- **“一键执行所有步骤（推荐）”** 按钮：带悬停提示，说明内含流程与注意事项。
- **新手提示文本**：指导首次使用者优先尝试此按钮。

### 4. 分步操作卡片（傻瓜式模式）

- **第 1 步：准备 XR 依赖包**
  - 说明将检查并安装 `XR Management / OpenXR / XR Interaction Toolkit`。
  - “执行第 1 步”按钮附带悬停提示，强调只进行依赖处理。
- **第 2 步：配置项目 & 场景**
  - 说明会启用 OpenXR Loader，并在场景中创建/更新 XR Rig，且在缺失时自动配置 XR Device Simulator（仅限傻瓜式模式）。
  - 当 Unity 正在编译时按钮会自动禁用并给出提示，避免误操作。

### 5. 专业模式卡片

- **步骤勾选**：可独立勾选“XR 依赖检查”“Project Settings 配置”“场景转换”。
- **目标平台选择**：可以单独为 Standalone 或 Android 生效，也可全选。
- **场景策略**：可在 `自动`、`仅更新现有 XR Origin`、`强制使用基础 VRRig`、`跳过场景转换` 之间切换，并可勾选“保留 Main Camera”。
- **调试选项**：新增“配置 VR 模拟设备（XR Device Simulator）”勾选项，仅在需要时才会导入 Sample 并启用。
- **执行按钮**：以“专业模式计划”名称触发，同样会走备份确认流程。

### 6. Git 助手联动卡片

- 当检测到 `com.fire.gitassistant` 时，会显示：
  - `打开 Git 助手`：直接跳转到 Git 助手窗口，方便人工处理复杂操作。
  - `使用 Git 助手快速备份`：自动调用 Git 助手执行 `git add -A` 与 `git commit`，生成一条“VR 转换前”备份提交。
  - `回滚到转换前版本`：在成功记录基线提交后启用，通过 Git 助手执行 `git reset --hard <基线>`，一键恢复。
- 若尚未检测到 Git 助手，则展示安装提醒，建议先完成版本控制配置。

### 7. 执行日志区域

- 记录所有动作的详细反馈（安装状态、配置是否成功、场景修改等）。
- 可滚动查看，便于排障或回顾操作历史。

## 操作流程

### 推荐流程：一键执行

1. 点击 **“一键执行所有步骤（推荐）”**。
2. 工具会先执行第 1 步（依赖检查/安装），等待包导入。
3. 若 Unity 此时正在编译，会在日志中提示等待；编译结束后自动继续第 2 步。
4. 第 2 步包含 XR 设置配置与场景 VR Rig 构建，最后在日志中汇总结果。
5. 若检测到项目尚未配置 XR Device Simulator，会自动复制 Sample 并启用“仅在编辑器自动实例化”选项。

### 分步操作

1. **执行第 1 步（依赖）**
   - 只会处理 `Packages/manifest.json` 中的 XR 相关条目。
   - 检测到 `"latest"` 占位符时会自动移除并重新安装。
   - 安装进度实时显示在日志中。
2. **执行第 2 步（配置 + 场景）**
   - 需要在 Unity 编译完成后点击，点击后会先弹出确认及保存提示，可随时取消。
   - 会为 `Standalone` 与 `Android` 启用 OpenXR Loader，并创建/更新 XR Origin。
   - 如 XR Interaction Toolkit 不可用，将自动退回到基础 VRRig。
   - 若你通过傻瓜式入口触发，系统还会检查并自动配置 XR Device Simulator，方便键鼠调试。

### 专业模式流程

1. 在模式切换条中选择 **“专业模式”**。
2. 在“专业模式计划”卡片中勾选需要执行的步骤，可自由组合：
   - 仅安装 XR 包；
   - 只更新 Project Settings；
   - 或只针对场景做 Rig 更新；
   - 需要时勾选“配置 VR 模拟设备（XR Device Simulator）”以复制 Sample 并启用设备模拟。
3. 选择目标平台：可只对 Standalone / Android 生效；若全部取消，会自动回退为默认双平台。
4. 为场景选择合适的策略：
   - **自动**：与傻瓜式模式一致，优先创建 XR Origin，缺失时退回 VRRig；
   - **仅更新现有 XR Origin**：不会新建对象，适合已有 XR 结构的项目；
   - **强制使用基础 VRRig**：跳过 XR Interaction Toolkit，直接生成轻量 Rig；
   - **跳过场景转换**：仅执行包/设置相关动作；
   - 可选 **“保留 Main Camera”**，避免自动禁用原主相机。
5. 点击 **“执行专业模式计划”**，同样会先经过备份确认。若检测到 Git 助手，可直接调用快速备份。
6. 结果将写入日志，并与 Git 助手卡片联动（可快速回滚）。

## Git 助手联动能力

- **执行前强制确认**：在点击“一键执行”或“第 2 步”时，会先弹出确认对话框。若检测到 Git 助手，可直接选择“使用 Git 助手快速备份”，由插件自动完成 `git add -A` + `git commit`，否则必须手动确认已备份才能继续。
- **快速备份按钮**：界面中的“Git 助手联动”卡片提供常驻的“使用 Git 助手快速备份”按钮，可随时生成“VR 转换前”提交，避免忘记。
- **回滚按钮**：当一轮 VR 转换成功后，且前置备份记录了 Git 提交，卡片会解锁 `回滚到转换前版本`。点击后会提示二次确认，并调用 Git 助手执行 `git reset --hard <记录的提交>`。
- **缺少 Git 助手时的指引**：若项目尚未安装 `com.fire.gitassistant`，界面会显示安装建议，你仍需通过其他方式完成备份才能继续。

## 功能详解

### 1. XR 依赖管理

- 检测并确保安装以下包：
  - `com.unity.xr.management`
  - `com.unity.xr.openxr`
  - `com.unity.xr.interaction.toolkit`
- 自动移除 manifest 中的 `"latest"` 占位符，避免包解析失败。
- 通过 `UnityEditor.PackageManager.Client.Add` 安装缺失依赖，状态写入日志。

### 2. XR Plug-in Management 配置

- 自动创建或复用 `XRGeneralSettingsPerBuildTarget` 资产，路径：
  - `Assets/VRConverterGenerated/XR/XRGeneralSettings.asset`
- 为 `Standalone` 与 `Android`：
  - 创建 `XR General Settings` 与 `XR Manager Settings`。
  - 确保 `Init Manager On Start` 开启。
  - 调用 `XRPackageMetadataStore.AssignLoader` 为两平台启用 `OpenXR Loader`。

### 3. 场景 VR Rig 构建

- 自动禁用旧的 `Main Camera`，防止重复渲染。
- 若检测到 `XR Interaction Toolkit`：
  - 创建或更新 `XR Origin (Action Based)` 层级。
  - 设置 `Camera Offset`、`Main Camera`、左右手控制器。
  - 自动添加 `Camera`、`AudioListener`、`TrackedPoseDriver`、`ActionBasedController`、`XRRayInteractor`、`LineRenderer` 等组件。
  - 创建 `XR Interaction Manager`、`XR Input Action Manager` 单例对象。
- 若缺少 XR Interaction 相关类型：
  - 自动生成基础 `VRRig`，包含 `CameraOffset`、`Main Camera`、左右手占位。

### 4. 日志与提示

- 所有操作都有时间戳记录，方便回溯。
- 对常见阻塞（如 Unity 正在编译）会给出明确提示。
- 失败的包安装、XR Loader 绑定等事件会附带原因。

### 5. 专业模式灵活度

- **步骤拆分**：可单独运行包安装、Project Settings 配置、场景转换任意组合。
- **目标平台过滤**：默认同时配置 Standalone + Android，可一键取消某一平台，便于桌面/移动专项项目。
- **场景策略**：
  - `自动`：与傻瓜式流程一致；
  - `仅更新现有 XR Origin`：不会创建新的 XR Origin，兼容已有定制 Rig；
  - `强制使用基础 VRRig`：跳过 XRI 依赖，只生成最小 VRRig；
  - `跳过场景转换`：完全不触碰场景，适合只想配置包/设置的场景；
  - `保留 Main Camera`：阻止工具自动禁用 `MainCamera`，避免多相机场景瞬时黑屏。

### 6. 项目体检（Compatibility Insights）

- 自动检测：
  - 当前渲染管线（Built-in/URP/HDRP 等）；
  - XR Management / OpenXR / XR Interaction Toolkit 是否可用；
  - 新输入系统（Input System package）是否已启用；
  - VR 模拟设备（XR Device Simulator）是否已配置为自动实例化；
  - Git 助手是否安装。
- 每项检测都会给出提示与下一步建议，帮助快速定位阻塞点。

### 7. VR 模拟设备（XR Device Simulator）

- 傻瓜式模式默认启用自动检查：如项目缺少 Sample，会将 `Packages/com.unity.xr.interaction.toolkit/Samples~/XR Device Simulator` 复制到 `Assets/VRConverterGenerated/DeviceSimulator`。
- 自动将 `Project Settings → XR Plug-in Management → XR Interaction Toolkit` 对应的 `XR Device Simulator` 设置成“仅在编辑器自动实例化”，避免打包体积膨胀。
- 专业模式可自主决定是否执行该步骤，方便已有模拟方案或不希望自动复制 Sample 的团队。

## 常见问题

**Q1：按钮灰色不可点击？**  
A：可能 Unity 正在导入/编译脚本。等待编译完成后再操作；头部状态条会同步提示当前状态。  

**Q2：执行第 1 步后没有立即生效？**  
A：安装 XR 包需要时间，也可能触发脚本重编译。等编译完成后再次执行第 2 步或“一键执行”即可。  

**Q3：日志提示未检测到 XR Interaction Toolkit？**  
A：请确认包已成功安装。如果暂时不可用，工具会自动使用基础 VRRig，仍可正常预览。  

**Q4：OpenXR Loader 未激活？**  
A：可能是 `XRPackageMetadataStore` API 版本差异导致。请在 `Project Settings → XR Plug-in Management` 中手动确认；工具在日志里会注明绑定失败。  

**Q5：场景中已有自定义 XR Rig，是否会被覆盖？**  
A：工具会检测并复用现有 `XR Origin` 或 `VRRig`。如担心冲突，建议先备份场景或使用版本控制。  

**Q6：执行后出现控制台错误？**  
A：请先查看窗口日志定位到具体步骤，再结合 Unity 控制台详情排查。常见原因包括：包安装失败、脚本编译错误或场景对象被锁定。  

**Q7：提示“XR Device Simulator prefab was missing, cannot automatically instantiate”？**  
A：最新版傻瓜式模式会自动复制 Sample 并启用设置，但若你禁用了该步骤或删除了生成资源，仍可能出现此提示。可重新执行傻瓜式“一键执行”或在专业模式勾选“配置 VR 模拟设备”。若仍未解决，请在 `Window → Package Manager → XR Interaction Toolkit` 中手动 **Import/Reimport** `XR Device Simulator` Sample，并在 `Project Settings → XR Plug-in Management → XR Interaction Toolkit` 中重新勾选对应选项。

## 注意事项与最佳实践

1. **使用前备份或提交（强制推荐）**：工具会修改 manifest、项目设置与当前场景，建议提前提交到 Git 或复制场景；若有 Git 助手可直接调用其“一键提交/撤销”能力。  
2. **保持网络畅通**：安装 XR 包需要访问 Unity 包仓库。  
3. **分步执行更安全**：若是生产项目，建议先手动执行第 1 步并确认依赖，再执行第 2 步。  
4. **日志即帮助**：遇到异常优先查看日志区域，按提示处理可大幅降低排查时间。  
5. **配合版本控制**：所有自动生成的资产保存在 `Assets/VRConverterGenerated` 下，方便追踪与回滚。
